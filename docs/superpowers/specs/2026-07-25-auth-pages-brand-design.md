# 认证与密码恢复页面品牌统一设计

## 1. 文档信息

- 日期：2026-07-25
- 基线版本：Sub2API `v0.1.164`
- 基线提交：`cd8bb98c44303b2c8f04c0da340447c992f0cb7d`
- 开发分支：`custom/frontend`
- 设计状态：用户已确认 C「品牌画册」方向及四种认证页面

## 2. 目标

将登录、注册、忘记密码和设置新密码页面从现有深色居中卡片改造成固定浅色的品牌认证界面，使其与“爱白嫖公益站”首页保持同一视觉体系，同时通过不同构图避免与首页完全重复。

最终页面应具备以下特征：

1. 沿用首页的浅蓝、白色、青绿色及少量暖色点缀。
2. 桌面端采用左侧品牌画册、右侧认证表单的双栏结构。
3. 登录、注册、忘记密码和设置新密码页面共享布局、配色、动态效果和响应式规则。
4. 网站图标在每个页面只出现一次，不再作为背景或装饰重复使用。
5. 保留现有登录、注册、密码恢复、OAuth、协议、验证码、错误提示和加载逻辑。
6. 不连接或修改生产数据，不改变后端认证接口。

## 3. 非目标

本次不包含以下内容：

- 修改首页内容或首页后台配置。
- 修改认证 API、密码规则、注册规则或数据库结构。
- 自定义、仿制或重绘 Cloudflare Turnstile 内部界面。
- 修改登录后的用户端、管理端页面。
- 增加新的认证方式。
- 将开发环境直接连接生产数据库。

## 4. 视觉方向

### 4.1 整体构图

页面使用浅色渐变背景，中心放置一张大尺寸圆角容器：

```text
认证页背景
└── 品牌认证容器
    ├── 左侧品牌画册区域
    │   ├── 网站图标 + 网站名称
    │   ├── 英文辅助标题
    │   ├── 品牌主文案
    │   ├── 两条服务特点
    │   └── 抽象线路节点装饰
    └── 右侧表单区域
        ├── 登录 / 注册切换
        ├── 页面标题与说明
        ├── 当前页面的真实表单
        ├── Turnstile（按配置条件渲染）
        ├── 协议确认
        ├── 主操作按钮
        └── 登录 / 注册互相跳转
```

左侧使用品牌叙事和抽象图形，右侧保持清晰、克制的表单结构。与首页的相同点是配色、圆角和可信赖感；不同点是更像一张品牌画册，而不是首页的宣传型 Hero 布局。

### 4.2 网站图标

- 使用用户提供的“爱白嫖公益站”图标。
- 图标只出现在左侧品牌区域顶部，每个页面仅一次。
- 不把该图标重复用作吉祥物、背景图、浮动卡片或底部装饰。
- 其余装饰使用圆形色块、虚线路径、节点和柔和渐变。
- 图标继续优先读取公开品牌设置中的 `site_logo`，并保留安全 URL 处理和默认 Logo 回退。

### 4.3 色彩与层级

主要颜色：

- 页面底色：极浅蓝绿与暖白渐变。
- 左侧品牌面板：浅青色。
- 表单面板：白色。
- 主操作色：青绿色。
- 点缀色：柔黄、浅橙、薄荷绿。
- 主文字：深蓝绿色。
- 次要文字：低饱和灰蓝绿色。

认证页面固定使用浅色主题，不跟随系统切换为深色。这样可确保其与当前自定义首页始终一致。

### 4.4 字体与间距

- 品牌标题使用较大字号、紧凑字距和较强字重。
- 表单标题保持明确但不与品牌标题争夺视觉焦点。
- 输入框、按钮、标签和提示文字沿用现有可访问性语义。
- 注册表单允许根据优惠码、邀请码、协议和 Turnstile 等条件自然增高。
- 不使用会裁切表单的固定高度，也不在表单内部制造独立滚动条。

## 5. 组件设计

### 5.1 `AuthLayout.vue`

`AuthLayout` 继续作为登录、注册、忘记密码和设置新密码的共享外壳，负责：

- 固定浅色页面背景。
- 桌面双栏与移动单栏布局。
- 左侧品牌区域。
- 唯一网站图标、网站名称和品牌文案。
- 抽象线路节点装饰。
- 右侧白色表单面板。
- 页面版权信息。
- 动态效果和减少动态效果适配。

默认插槽继续承载登录或注册表单，页脚插槽继续承载登录/注册互相跳转，不把认证业务逻辑移动进布局组件。

### 5.2 登录 / 注册切换

增加一个职责单一的共享切换组件，例如 `AuthModeTabs.vue`：

- `activeMode` 仅接受 `login` 或 `register`。
- 点击后使用 Vue Router 导航至 `/login` 或 `/register`。
- 不保存额外状态，不自行提交表单。
- 当前模式具有明确的视觉选中态和 `aria-current` 信息。

登录页和注册页分别传入当前模式，避免复制切换栏样式和逻辑。忘记密码和设置新密码页面不显示登录/注册切换栏，而是提供明确的“返回登录”入口。

### 5.3 `LoginView.vue`

保留现有全部行为：

- 邮箱和密码输入。
- 显示或隐藏密码。
- 忘记密码入口。
- 登录协议。
- Turnstile。
- GitHub、Google、LinuxDo、钉钉、微信和 OIDC 等条件式 OAuth 区域。
- 2FA 流程。
- 加载、禁用和错误状态。

仅调整视觉结构、间距和与共享布局的组合方式。

### 5.4 `RegisterView.vue`

保留现有全部行为：

- 邮箱、密码、邀请码和优惠码。
- 邮箱验证流程。
- Turnstile。
- 登录协议。
- OAuth 注册。
- 注册关闭提示。
- 校验成功、失败、加载和禁用状态。

注册页内容高度由实际开启的字段决定，右侧面板和整个页面随内容自然增长。

### 5.5 `ForgotPasswordView.vue`

保留现有全部行为：

- 邮箱输入。
- Turnstile 条件式渲染。
- 发送重置链接。
- 提交加载和按钮禁用状态。
- 邮件发送成功状态。
- 返回登录入口。

页面使用同一品牌画册布局，右侧表单仅显示密码恢复所需内容。真实 Turnstile 出现时自然撑开表单，不覆盖发送按钮。

### 5.6 `ResetPasswordView.vue`

保留现有全部行为：

- 重置链接中的邮箱只读显示。
- 新密码和确认新密码输入。
- 密码显示或隐藏。
- 链接无效状态。
- 密码重置成功状态。
- 重新申请链接和返回登录入口。

该页面沿用现有业务逻辑，不增加 Turnstile。链接无效、重置成功和正常表单三种状态均在右侧面板中显示。

### 5.7 国际化

新增品牌画册所需文案应进入现有 i18n 资源，不在 Vue 模板中只硬编码中文。至少包含：

- 品牌辅助标题。
- 品牌主标题。
- 品牌说明。
- 清楚计费特点。
- 灵活调度特点。
- 返回首页文案。

网站名称继续来自公开设置，不硬编码为固定站名。

## 6. Turnstile 行为

登录页、注册页和忘记密码页都必须保留现有真实 `TurnstileWidget`，不得使用 Demo 中的静态检测界面。设置新密码页继续保持现有逻辑，不增加 Turnstile。

渲染规则：

```text
turnstileEnabled && turnstileSiteKey
    ├── true  → 挂载 Cloudflare TurnstileWidget
    └── false → 不渲染、不占空间
```

启用后：

1. Cloudflare 官方组件在表单指定位置自动渲染。
2. 组件自然撑开表单高度，后续协议和按钮顺序下移。
3. 未取得 Token 前，提交按钮保持禁用。
4. 验证成功、过期和错误事件继续由现有回调处理。
5. 只设置外围容器宽度和上下间距，不修改 Cloudflare iframe 内部样式。

登录、注册和忘记密码都按相同规则处理，避免某一页面出现覆盖、裁切或按钮错位。

## 7. 动态效果

动态效果保持低强度、低干扰：

- 页面容器入场：约 600–750ms 的淡入和轻微上移。
- 背景色块：约 11–15s 的缓慢漂移。
- 左侧抽象线路：约 6s 的轻微呼吸变化。
- 节点：约 3.5–4.5s 的小范围浮动，并使用不同延迟。
- 网站图标：约 4.8s 的小幅垂直浮动，悬停时轻微倾斜和放大。
- 登录/注册切换：约 350–400ms 的淡入上移。
- 输入框：悬停或聚焦时显示柔和青绿色描边和外环。
- 主按钮：悬停时轻微上浮，并出现一次性光泽扫过。

禁止使用快速闪烁、大幅摇摆、持续缩放或大量粒子。

所有动画必须支持：

```css
@media (prefers-reduced-motion: reduce)
```

在减少动态效果模式下关闭非必要动画和过渡。

## 8. 响应式设计

### 8.1 桌面端

- 使用左右双栏。
- 容器最大宽度约 1080–1140px。
- 两栏宽度接近 1:1，允许表单区域略宽。
- 左侧品牌区域随注册表单自然增高。

### 8.2 平板和窄屏

- 当可用宽度不足时切换为上下单栏。
- 品牌区域压缩为较短的顶部品牌介绍。
- 隐藏非必要服务特点，保留唯一网站图标、网站名称、主文案和轻量节点装饰。

### 8.3 手机端

- 页面左右留白至少 14–16px。
- 表单区域使用单列全宽布局。
- 输入框、按钮和 Turnstile 容器不得超出视口。
- 页面允许正常纵向滚动。
- 登录和注册切换保持可点击区域充足。
- 忘记密码和设置新密码页面的“返回登录”“重新发送”入口保持清晰可见。

## 9. 数据流与状态

```text
应用启动
  → AuthLayout 读取 appStore 公开品牌设置
  → 显示 siteName / siteLogo / siteSubtitle
  → 当前认证视图读取所需公开设置和路由参数
  → 按页面与配置显示字段、协议、OAuth 与 Turnstile
  → 用户提交
  → 继续调用现有认证 API
  → 使用现有 Toast、错误消息、2FA 或跳转流程
```

本次不增加新的 API 调用，也不改变请求参数。

## 10. 错误与边界状态

- 公开设置加载失败时继续使用现有默认品牌值，认证表单仍可显示。
- Logo URL 无效时继续使用默认 Logo。
- 注册关闭时保留现有关闭提示，不渲染不可用表单。
- Turnstile 加载失败、过期或验证错误时继续使用现有事件处理和按钮禁用逻辑。
- OAuth 全部关闭时不显示分隔线和 OAuth 区域。
- 忘记密码功能关闭或后端模式开启时不显示忘记密码入口。
- 忘记密码邮件发送成功时显示确认状态并提供返回登录入口。
- 重置链接无效时显示明确错误状态并提供重新申请链接入口。
- 密码重置成功时显示成功状态并提供登录入口。
- 表单校验错误必须保持现有错误颜色、提示信息和焦点行为。

## 11. 测试策略

### 11.1 自动化测试

新增或更新测试以覆盖：

- `AuthLayout` 只渲染一个网站图标。
- Logo 使用公开设置并保留安全 URL 处理与默认回退。
- 登录 / 注册切换导航正确。
- 登录页启用 Turnstile 时渲染真实组件，关闭时不渲染。
- 注册页启用 Turnstile 时渲染真实组件，关闭时不渲染。
- 忘记密码页启用 Turnstile 时渲染真实组件，关闭时不渲染。
- 忘记密码页覆盖提交中和邮件发送成功状态。
- 设置新密码页覆盖正常、无效链接和重置成功状态。
- 设置新密码页不新增 Turnstile。
- 条件字段、OAuth、协议和现有认证行为没有回归。
- 移动端类名和结构不产生固定宽度溢出。

完成后运行：

```powershell
corepack.cmd pnpm@9 run typecheck
corepack.cmd pnpm@9 run lint:check
corepack.cmd pnpm@9 run test:run
corepack.cmd pnpm@9 run build
```

已知基线问题：`v0.1.164` 的 `admin.system.rollback.spec.ts` 有两个过期断言，原因是实现增加了 15 分钟超时配置但测试未同步。认证页改造不得增加新的测试失败。

### 11.2 手动检查

至少检查以下组合：

- 桌面登录页：Turnstile 开启和关闭。
- 桌面注册页：Turnstile、优惠码、邀请码和协议的不同组合。
- 桌面忘记密码页：Turnstile 开启、关闭和邮件已发送状态。
- 桌面设置新密码页：正常、链接无效和重置成功状态。
- 手机端四种认证页面。
- Logo 正常、缺失和非法 URL 回退。
- 加载、错误、禁用和提交中状态。
- `prefers-reduced-motion` 开启状态。

## 12. 验收标准

满足以下条件视为设计实现完成：

1. 登录、注册、忘记密码和设置新密码均采用 C「品牌画册」浅色双栏设计。
2. 每个页面只出现一次网站图标。
3. 四个页面的所有现有功能和状态保持可用。
4. Turnstile 使用真实组件，登录、注册和忘记密码都能按配置自动出现或隐藏；设置新密码不新增 Turnstile。
5. Turnstile 出现时不覆盖协议、按钮或其他字段。
6. 主按钮文字在所有状态下水平、垂直居中。
7. 桌面、平板和手机均无横向溢出或内容裁切。
8. 动画克制，并支持减少动态效果设置。
9. 类型检查、Lint 和生产构建通过。
10. 除已记录的两个上游基线断言外，不新增测试失败。
